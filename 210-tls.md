# TLS (SSL)
Assuming you own the example.com domain and you can create TXT records on the domain.
`PUBLIC_NAME` in `/etc/lanparty/env` is the name the certificate is for (e.g.
`lan.example.com`); without it this doc does nothing. `FEATURES` with `godaddy` uses the
automated DNS challenge below instead of the manual one.

On the party LAN dnsmasq answers that name with the server itself:
`/etc/dnsmasq.d/tls.conf`
```ini file=/etc/dnsmasq.d/tls.conf
address=/${PUBLIC_NAME}/10.10.0.1
```

```sh run
systemctl restart dnsmasq
apt install -y certbot
```

**1. Request the certificate** (the manual way; with `godaddy`, see "SSL ACME" below):

```sh manual if=!feature:godaddy
certbot certonly --manual --preferred-challenges dns \
    --agree-tos -m notify-on-expiry@gmail.com -d lan.example.com
```

**2. It prints the record to create**, then waits for Enter:

```
Please deploy a DNS TXT record under the name:
_acme-challenge.lan.example.ch
with the following value:
Xf9...   (a long random string)
```

**3. Add it at your DNS provider.** Host/name `_acme-challenge.lan` (most panels append
the zone for you), type `TXT`, value exactly as printed, TTL as low as the panel allows.

**4. Confirm it is live before pressing Enter**, from any machine with internet. Ask the
zone's own nameserver rather than a cache: if anything looked the name up before you
created it, public resolvers hold the negative answer for as long as the zone's SOA
says, and will keep reporting nothing long after the record is live.

```sh
dig +short NS example.com                               # e.g. ns1.provider.net
dig +short TXT _acme-challenge.lan.example.com @1.1.1.1 # must print the value
```

**5. Press Enter.** The result:

```
/etc/letsencrypt/live/lan.example.ch/fullchain.pem
/etc/letsencrypt/live/lan.example.ch/privkey.pem
```

**6. Enable SSL on the lan.example.com**
`/etc/apache2/sites-available/lanparty-ssl.conf` -- other docs add to this vhost through
`/etc/apache2/lanparty-ssl.d/` (e.g. `442-liveboot-menu.md`).
```apache file=/etc/apache2/sites-available/lanparty-ssl.conf
<VirtualHost *:443>
    ServerName ${PUBLIC_NAME}

    SSLEngine on
    SSLCertificateFile    /etc/letsencrypt/live/${PUBLIC_NAME}/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/${PUBLIC_NAME}/privkey.pem

    # Deliberately no HSTS header and no redirect from port 80. Both would force the
    # whole hostname to HTTPS, and the iPXE boot chain cannot follow.

    IncludeOptional /etc/apache2/lanparty-ssl.d/*.conf
</VirtualHost>
```

Apache refuses to start with a vhost whose certificate does not exist yet, so the site is
only enabled once it does (apply this doc again after step 5):
```sh run
mkdir -p /etc/apache2/lanparty-ssl.d
if [ -s "/etc/letsencrypt/live/$PUBLIC_NAME/fullchain.pem" ]; then
	a2enmod ssl
	a2ensite lanparty-ssl
	apache2ctl configtest
	systemctl reload apache2
else
	echo "no certificate for $PUBLIC_NAME yet -- request it first, then apply this doc again"
fi
```

```sh verify
# the certificate exists and is good for at least another week (offline, nobody renews it)
openssl x509 -checkend 604800 -noout -in "/etc/letsencrypt/live/$PUBLIC_NAME/fullchain.pem" >/dev/null ||
	{ echo "certificate for $PUBLIC_NAME is missing or expires within 7 days"; exit 1; }
```

```sh verify
# the public name resolves to this server on the LAN and serves a valid certificate
getent hosts "$PUBLIC_NAME" | grep -q '10\.10\.0\.1' || { echo "$PUBLIC_NAME does not resolve to 10.10.0.1"; exit 1; }
# online, the public DNS may answer that as well; offline only dnsmasq's own entry does
grep -qsx "address=/$PUBLIC_NAME/10.10.0.1" /etc/dnsmasq.d/tls.conf || { echo "dnsmasq has no entry for $PUBLIC_NAME"; exit 1; }
curl -sS -o /dev/null --max-time 5 "https://$PUBLIC_NAME/" ||
	{ echo "HTTPS on $PUBLIC_NAME failed (certificate or vhost)"; exit 1; }
```

## SSL ACME
For godaddy:
1. developer.godaddy.com > Generate Token
Use domains.domain:read and domains.dns.update

2. store configuration (it holds the token, so it is written by hand)
```sh manual if=feature:godaddy
sudo vi /etc/letsencrypt/godaddy.env # TOKEN=... (newline) ZONE=example.com
sudo chmod 600 /etc/letsencrypt/godaddy.env
```

3. the ACME script (it needs `dig` and `jq`)
```sh run if=feature:godaddy
apt install -y bind9-dnsutils jq
```
`/usr/local/sbin/godaddy-acme`
```sh file=/usr/local/sbin/godaddy-acme mode=0755 if=feature:godaddy
#!/bin/sh
# certbot DNS-01 hook for GoDaddy. Called as: godaddy-acme auth | cleanup
# certbot supplies CERTBOT_DOMAIN and CERTBOT_VALIDATION in the environment.
set -eu
. /etc/letsencrypt/godaddy.env

API="https://api.godaddy.com/v3/domains/zones/$ZONE/dns-records"
AUTH="Authorization: Bearer $TOKEN"

case "$CERTBOT_DOMAIN" in
    "$ZONE") NAME="_acme-challenge" ;;                       # apex
    *)       NAME="_acme-challenge.${CERTBOT_DOMAIN%.$ZONE}" ;;
esac
FQDN="$NAME.$ZONE"

case "${1:-}" in
auth)
    curl -sSf -o /dev/null -X POST "$API" -H "$AUTH" -H "Content-Type: application/json" \
        -d "{\"type\":\"TXT\",\"name\":\"$NAME\",\"data\":\"$CERTBOT_VALIDATION\",\"ttl\":600}"
    # Every authoritative NS must serve it
    n=0
    while :; do
        ok=1
        for ns in $(dig +short NS "$ZONE"); do
            dig +short TXT "$FQDN" @"$ns" | grep -qF "$CERTBOT_VALIDATION" || ok=0
        done
        [ "$ok" = 1 ] && break
        n=$((n + 1))
        [ "$n" -gt 36 ] && { echo "TXT not on all NS after 3 min" >&2; exit 1; }
        sleep 5
    done
    ;;
cleanup)
    # Match on the value, not just the name: a wildcard challenge puts a second
    # TXT at the same name and must survive.
    ID=$(curl -sSf "$API?type=TXT&name=$NAME" -H "$AUTH" |
         jq -r --arg v "$CERTBOT_VALIDATION" \
            '.. | objects | select(.data == $v) | .recordId // .id' | head -1)
    [ -n "$ID" ] && curl -sSf -X DELETE "$API/$ID" -H "$AUTH"
    ;;
esac
```

4. first run
```sh manual if=feature:godaddy
sudo certbot certonly --manual --preferred-challenges dns \
    --manual-auth-hook    "/usr/local/sbin/godaddy-acme auth" \
    --manual-cleanup-hook "/usr/local/sbin/godaddy-acme cleanup" \
    --deploy-hook         "systemctl reload apache2" \
    -d lan.example.com
```
Validate (needs internet):
```sh
sudo certbot renew --dry-run
```

```sh verify if=feature:godaddy
# renewals run on their own: certbot's timer and the hook it calls are in place
systemctl is-enabled --quiet certbot.timer
grep -q '^manual_auth_hook = /usr/local/sbin/godaddy-acme auth' "/etc/letsencrypt/renewal/$PUBLIC_NAME.conf"
[ "$(stat -c %a /etc/letsencrypt/godaddy.env)" = 600 ]
```
