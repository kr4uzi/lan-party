# NTP (time server)
The server is designed to operate (temporarily) offline, and having a server providing a somewhat accurate time helps for certificate validation and so on.

```sh run
apt install -y chrony   # Ubuntu Server ships it; this only makes sure
```

`/etc/chrony/conf.d/lanparty.conf`
```ini file=/etc/chrony/conf.d/lanparty.conf
# Installing chrony is not enough to be an NTP server: by default it answers nobody.
# DHCP option 42 points clients here, so the LAN has to be allowed. Phones joining
# through a bridged wifi router are on this same LAN — no separate subnet to allow.
allow 10.10.0.0/24
allow fd10:10::/64

# Keep serving time when the uplink is gone. Stratum 10 is low enough that any real
# upstream wins once the internet comes back, and high enough that clients accept it
# meanwhile — which is what makes certificate validation work at an offline party.
local stratum 10
```
```sh run
systemctl restart chrony
```

```sh verify
# chrony answers NTP on the LAN address (a real, read-only exchange: -Q sets no clock)
systemctl is-active --quiet chrony
chronyd -Q 'server 10.10.0.1 iburst maxsamples 1' 2>&1 | grep -q 'System clock wrong by' ||
	{ echo "no NTP answer from 10.10.0.1: check the allow lines"; exit 1; }
```
